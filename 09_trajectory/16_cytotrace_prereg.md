**换到原文自己的路**。源论文（彭 2026 *Cancer Cell*）的"发育轴" = 上皮分化轴
**AT2 → AIC → KAC → 前驱 → 浸润**，用 **monocle3 拟时序 + CytoTRACE**（Gulati 2020 *Science*）刻画。

## §3 输入（已逐项核验，2026-09-27）

| 项 | 值 |
|---|---|
| 细胞 | 上皮 **133,384**（全项目统一口径） |

| 期别 | `obs.stage` ∈ {Normal 32,251 / AAH 11,891 / AIS 28,525 / MIA 4,583 / IAC 56,134} |
| 患者 | `obs.patient_id`（23 例） |

**工具（零安装，已核验）**：`cellrank 2.0.5` 的 `CytoTRACEKernel.compute_cytotrace()`
是 **Gulati 2020 CytoTRACE 的复刻**。monocle3 / CytoTRACE(R) / CytoTRACE2 **均未装**。

**平滑层 `Ms`（一处实现替代，已实测登记）**：CellRank 默认吃 `Ms` 层
（kNN 平滑 ≈ 原版 CytoTRACE 用的 MAGIC 那一步）。原计划用已装的 `scvelo 0.2.5`
的 `scv.pp.moments()` 生成，**实测它在我们这种只有 `X` 的对象上直接跳过**：

> `WARNING: Skipping moments, because un/spliced counts were not found.` ⇒ `KeyError: 'Ms'`

故改为**自己按连通度算**：`Ms = D⁻¹ A X`，其中 `A = adata.obsp['connectivities']`、
`D = A 的行和`。这与 scvelo 生成的 `Ms` **定义相同**（都是一阶 kNN 均值），
不是口径改变，是换了个执行者。已小样本端到端验证通过。

**`compute_cytotrace()` 产出的三列（实测）**：`ct_score`（主分数）、`ct_pseudotime`、
**`ct_num_exp_genes`（= 检出基因数）**。最后这列直接就是 C4 要的深度代理。

## §4 主检验与判据（事前写死，不得事后调）

**方向预测**（来自原文那条轴）：**CytoTRACE 分数随病程单调下降**
（Normal 最高 → IAC 最低）。理由：CytoTRACE 高 = 发育潜能高/原始；
原文轴的起点 AT2 是肺泡祖细胞，终点是浸润灶。

**四条判据，全过才叫 PASS**：

- **C1 单调**：五个期别的 CytoTRACE 中位数**严格递减**（不允许并列）。
- **C2 显著**：Kruskal–Wallis `p < 0.01` **且** 期别 **`η² ≥ 0.06`**
  （Cohen 对 η² 的惯例中效应值：0.01 小 / **0.06 中** / 0.14 大）。
- **C3 不是患者效应**：`η²_患者 < 0.5`。
- **C4 不是深度代理**：报告 `corr(CytoTRACE, nFeature)`；
  **若 |r| ≥ 0.9 ⇒ 判定降级为「本读数主要在测测序深度」**，不得写成发育结论。

**⚠️ 方向若相反**（IAC 最高）：**照实报**，并记为该轴**在我们队列上被证伪**，
不得调头重述成"其实和原文一致"。

## §8 诚实边界（写在前头）

1. **CytoTRACE 的本质是"检出基因数 + top-200 相关基因"**，天生与测序深度共线。
   原文也在同一个陷阱里。C4/K1 就是为了把它摊开。
2. **口径缺口已登记**（§2）：我们测的不是原文的亚型轴，是分期轴。
3. 我们**已经知道**前驱三期在恶性判别上是地板（scMalignantFinder 前驱 p90 ≤ 0.018）。
   ⇒ **若 §4 也不过，那是"生物学梯度本身就平"的又一条证据，不是方法没选对。**
4. CytoTRACE 平滑后的分数**不是独立观测**——它是同批细胞表达的函数，
   §5 的对照能查"是不是深度/患者"，但**查不出"是不是循环论证"**（因为无处可查）。
