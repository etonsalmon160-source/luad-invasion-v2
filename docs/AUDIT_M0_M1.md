## 2. 已定位并修复的问题

| 问题 | 根因 | 影响 | 处置 |
| :--- | :--- | :--- | :--- |
| `cell_barcode` 全为 `"0\|<样本>"` | `fread` **autostart 跳过条码行**（首行字段数≠数据行） | 标识失效、无法 join；且丢 1 个基因 | 单独读条码行 + `skip=1` + `stopifnot` 断言；**全量重跑** |
| 修复后数据行多丢一行 | `dt[-1,-1]` 重复丢行 | 基因数与矩阵不符（即时报错） | 改 `dt[,-1]` |
| `P7_LUAD` 双体率 = 0 | **scDblFinder `xgb` 分类器塌缩**（非生物学；同患者另两样本正常） | 该样本无剔除 | 改 `score="weighted"` → 11.69%；**主脚本加自动 fallback** |
| 归一化丢失 GEO 原始标签 | `LUAD` → `IAC` 后无回溯 | 透明性不足 | 冻结表新增 **`stage_token`** 列保留原标签 |
| 空间样本无 GSM | 源文件表未记目录名中的 GSM | 可追溯性不足 | 源文件表新增 **`gsm`** 列 |

## 3. 已知限制（不阻断，但下游须声明）

**① 空间数据本地 56/56 张切片 —— 其中 1 张曾截断，已修复（2026-09-22）**
GSE307534 GEO 全量 56 样本；本地已解压 **56**。曾有的唯一缺陷：`GSM9226176`
的 tar 仅 56,272,384 B（应为 90,677,930 B），`gzip -t` 报 unexpected EOF
→ 缺 `spatial/scalefactors_json.json` 与 `spatial/tissue_positions.csv`
（**虽保住表达矩阵，但缺坐标 ⇒ 该样本无法做任何空间分析，不是"能凑合用"**）。

✅ **2026-09-22 已修复（用户明确授权写入只读源目录）**：

| 项 | 内容 |
| :--- | :--- |
| 装入件 | `GSM9226176_P4_AAH-1.tar.gz`，90,677,930 B，sha256 `e501041e201dac78c9bd3f8a3f02f64e704062eb895bdecd61e9b335f7a6649e` |
| 完整性 | `gzip -t` 通过（rc=0） |
| 内容 | 16 个 tar 条目 / 13 个文件，含 `tissue_positions.csv`（14,337 行）与 `tissue_positions_list.csv` |
| 数据量 | barcodes 12,295 点、features 18,120 基因、矩阵 53 MB / 15,138,265 非零 |
| 定位复核 | `locate_slide()` 实测 → 候选**唯一**（`P4_AAH2`）、缺失文件**无** ✓ |
| 备份 | 坏 tar 与旧的半成品解压目录移至 `scratch/m0_backup_20260922/`（**不留在数据根**，留住证据） |

⚠️ **两条更正（本项目记录曾/曾可能出错的地方）**：

1. 🔴 **"解压出两个切片根 ⇒ `locate_slide()` 因候选≠1 拒收"是错的。**
   该 tar 自始至终**只有一个根** `P4_AAH2`。曾被误认作"第二个根"的 `P4_AAH_1`
   是解压目录里的**符号链接**（建于 2026-08-06，指向 `P4_AAH2`），不是 tar 的条目。
   且 `locate_slide()` 用 `os.walk(followlinks=False)`（默认），**不会**跟进符号链接，
   故它**从未**产生第二个候选 —— 2026-09-22 实测 `候选数 = 唯一`。
   本文 §3-① 原先就写的是"只有一个切片根"，**是对的**；错误说法只出现在外部计划文件里。
2. 🔴 **门的真实失败原因只有一条：文件缺失（C8）**，即截断导致的 `spatial/` 全丢。
   修复后 M0 门由 **FAIL → PASS**（八条判据全绿；见 `results/00_ingest/paired_manifest.json`）。

⚠️ **`tar tzf` 抓不住这个坏件**：它对截断件返回 0 且能列出 7 个条目。
**M0 的完整性检查必须用 `gzip -t`（或完整解压），不能只看 tar 能不能列。**

⚠️ **`P4_AAH2` 目录名与样本名 `P4_AAH-1` 不对板**：这是 GEO 侧的命名（该患者第二个
AAH 区在源头就叫 `P4_AAH2`），**好件与坏件都一样**，不是截断造成的。既有的
`locate_slide()` **不靠目录名猜**、靠"含 `filtered_feature_bc_matrix` 的唯一候选"定位，
故不受影响 —— **无需改名**。此项已核，不再是待办。

⚠️ **附带发现（非本次改动引入）**：冻结于 2026-09-15 的那份 manifest 记的
`registry_sha256` 对应 `00_ingest/cohort_registry.py` 的 `02f0472`（09-15）版；
该文件在 **09-17（`2378cac`）** 被改过，故 09-15 之后门一直"比 registry 旧"。
**核对结论：该改动不实质**——只删了一个常量 `SECOND_LESION_SUFFIX`、把一个
**从未被任何代码调用**的 `lesion_ordinal()`（按 `-1` 后缀猜序号，见 `GP1_report.md` §6.1）
换成查 GEO 表的 `resolve_lesion_ordinal()`，外加注释扩写。
`STAGE_MAP` / `STAGES` / `COHORTS` 逐行未动，且 **GEO 权威表哈希未变**
（`geo_tables_sha256` 前后相同）⇒ **门翻盘只能归因于样本修复，不可能是 registry 换版。**

**② 患者身份来自 GEO 标题推断**
GEO 无独立 `patient id` 字段；`P*` 编号取自标题 `… of patient N`（标题本身是 GEO 权威）。
配对关系（**23 例**）据此建立 —— 已落为 **GEO 权威样本表** `00_ingest/geo_metadata/*_samples.tsv`（逐 GSM 交叉核验，0 不一致）。

**③ 阶段归一化 `LUAD → IAC` 为本项目约定**
该研究以 `LUAD` 命名浸润期样本（与 AIS/MIA 并列），故归一为 `IAC`。原始标签已保留于 `stage_token`。

**④ 双体检测为单一方法**
第二方法在本环境不可行：**scrublet** 在稀疏核上可检测比例仅 ~0.5%；**DoubletFinder** 需 Seurat 2/3 或 5，本机为 4.3.0。
→ 以两项独立验证替代（计数特征、跨谱系共表达），并**如实声明**。

**⑤ 双体剔除比例有一定敏感性**
主结果与固定 top-10% 重合约 **62.3%** → 关键分析处**必须做"剔/不剔双体"下游敏感性**。

**⑥ 汇总双体率 15.48% 具误导性**
为**按细胞数加权**（大样本拉高）；"典型样本"率为中位 **10.6%**。应**逐样本呈现**并注明为模型估计。

**⑦ 空间 spot QC 未做**
M1 仅覆盖 GSE308103（snRNA）；GSE307534 的 spot 级 QC 属空间前处理，尚未执行。
